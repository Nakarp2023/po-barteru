## Почему не назначаем роль из браузера
`app_metadata` меняется только доверенной серверной стороной через Supabase Auth Admin API. Service Role Key нельзя помещать в HTML, JS, репозиторий или клиентское приложение.

## Безопасный вариант первоначальной активации
1. Создать отдельную Edge Function `admin-bootstrap` (не использовать старую `support-telegram-setup`).
2. Включить обязательный секрет `ADMIN_BOOTSTRAP_SECRET` в Secrets Staging.
3. В коде функции разрешить строго один UID (см. выше), проверять действующую пользовательскую JWT и сравнение секрета в серверной среде; не возвращать/логировать секрет.
4. Функция использует только серверный `SUPABASE_SERVICE_ROLE_KEY`, назначает `app_metadata: { role: "admin" }` конкретному UID через Auth Admin API и выполняет одноразовое погашение секрета (атомарно в БД).
5. Удалить/отключить bootstrap после успешного назначения роли; далее управлять ролями только доверенным операционным процессом.
6. Выйти и войти заново, чтобы получить обновлённый JWT. Проверить доступ к панели, RPC, журналу и отказ обычного аккаунта.
