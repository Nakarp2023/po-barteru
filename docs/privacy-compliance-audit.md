# ПО БАРТЕРУ — предварительный privacy/compliance audit (РФ)

Дата: 09.11.2026  
Статус: рабочий чек-лист, не юридическое заключение. Перед публичным запуском текст и процессы должен проверить профильный юрист; неизвестные реквизиты оператора намеренно не заполнены.

## 1. Что уже реализовано в интерфейсе (ветка privacy-consent-ui)

- Отдельный checkbox согласия на обработку персональных данных в регистрации; регистрация блокируется без отметки.
- Версия текста и timestamp согласия передаются в metadata регистрации Supabase Auth. **Это технический след, но metadata пользователя редактируемы и не заменяют серверный журнал согласий.**
- Cookie-панель информирует о необходимых технологиях и отсутствии включенной аналитики/рекламы; выбор сохраняется локально.
- Раздел управления cookie и запросом удаления данных находится в профиле/«Информация и помощь».
- Запрос удаления сейчас не удаляет учетную запись автоматически: обращение направляется в поддержку.

## 3. Безопасный сценарий удаления аккаунта (проектное решение)

1. Пользователь инициирует запрос из настроек, подтверждает намерение повторной авторизацией/подтверждением.
2. Сервер проверяет JWT и принадлежность account ID; клиент не передает произвольный user_id для удаления.
3. Edge Function с service role (только secret на сервере) создает заявку/аудит, блокирует новые действия и выполняет согласованный план.
4. Проверяется наличие незавершенных сделок, споров, жалоб, платежей/обязательств и законных сроков хранения. При наличии — объяснить пользователю, что сохранится и почему; при необходимости сначала закрыть процесс.
5. Публичный профиль и необязательные персональные данные удаляются или обезличиваются; сообщения/сделки обрабатываются по утвержденной политике, не разрушая доказательства и права других участников.
6. Auth user удаляется только после завершения допустимой очистки и проверки; затем завершаются сессии, очищается локальное состояние и пользователь видит итог/срок.
7. Отдельный минимальный журнал операции хранится в пределах обоснованного срока, без избыточных данных.

**Важно:** нельзя безопасно реализовать финальное автоматическое удаление, пока не сверены реальные таблицы/foreign keys/RLS и требования к сохранению сделок. Ветка содержит только интерфейс запроса, не destructive SQL и не автоматическое удаление.
